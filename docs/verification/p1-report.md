## 已处理的问题

1. **Toil Worker 环境。** 直接调用可执行文件时，子进程找不到 `_toil_worker`；启动时明确使用独立虚拟环境的 PATH，并清除 PYTHONPATH 覆盖。
2. **嵌套步骤的路径丢失。** Toil 9.5.0 的 job 名称会缩短父路径。给固定夹具分配静态路径 tool ID，保存映射，再用消息总线与 scatter 序号验证身份；没有修改引擎私有实现。
3. **取消测试可能过早通过。** 改为等待实际工具启动标记，核实其为引擎子进程，取消后验证后代消失与无输出；不以“请求接受”作为停止证据。
4. **Weaver 部署与测试配置。** 补充 Docker CLI、镜像路径一致性、合法的内部域名、并发 HTTP Worker、本地数据源与 MongoDB result backend；重启后重新发现临时端口；内部工作流引用进程地址而不是重复追加 `/package`。
5. **Weaver 输出路径与下载。** 默认文件路径清理会移除 `.p1-runtime` 的前导点，导致结果文件路径不一致；改用容器内普通绝对路径 `/v7-p1-outputs`。根据上游配置要求，为结果 URL 配置独立只读文件服务并复验，而不是把缺失的下载部署误判成计算失败。
6. **gVisor 安装与部署。** 按当前官方发行格式校验并解包 tar 归档；本机 rootless 不可用，另验证专用包装容器配置。未修改宿主 Docker daemon。
7. **隔离负例本身的可靠性。** 输入文件设为普通权限可写再验证只读挂载；用 `/proc/net/dev` 检查仅 loopback；临时目录填满时，错误信息不写入已满的同一文件系统。

## 支持范围和缺口

Toil 当前只验证固定、受信任的 Linux 本地夹具。句柄文件不具备数据库事务和跨主机一致性；真实主机掉电、分布式 Worker、引擎与 gVisor 联调尚未验收。UNKNOWN 保留待核对，不自动补跑。

gVisor 通过的配置需要有权限的可信外层运行时。guest 无权限与网络；该结论不能扩大成 rootless 成功或完整逃逸防护证明。CPU／内存限制已配置但未压力测试，临时目录容量限制已实际触发。

Weaver 的每项失败仅代表本次固定版本与部署未达到门槛。对照实验保留可复现的配置、HTTP 和服务日志，没有修改上游代码来跳过失败。启动时访问外部 Schema，完整离线冻结尚未解决。

未执行真实模型、业务数据库事务、预算、租约、outbox、科学数值验收、资产发布、QGIS、远程执行、长工作流或性能压测：这些属于后续阶段，当前没有对应业务实现。
