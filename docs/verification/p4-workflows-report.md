## 开发中发现并修复的问题

## 当前限制

- P4.1 只声明同一主机、同一 Docker daemon 和持久 Execution 工作目录上的恢复能力。已有单次固定负载基线，但未验证跨主机接管、主机掉电、备份恢复、版本回退、持续多租户负载或生产 SLA。
- CWL 是明确受限子集，不支持用户 JavaScript、ExpressionTool、Shell、运行时外部 import、任意镜像或服务地址。动态节点在取得平台许可前受 1,000 节点和父额度约束。
- 生产算子目录仍只有 P3 的完整率和描述性线性趋势。其他工作流执行成功只证明执行和发布完成，不构成科学结论验收。
- QGIS、制图、远程执行、Knowledge、Agent 和生成代码执行未实现。rootless gVisor 不是本轮依赖或验收条件。
- 验收数据是可审计合成时间序列，不是真实地下水观测。P1 的 Weaver/gVisor 重型历史实验未重跑；本轮真实运行了 Toil、cwltool 和节点容器。

## `0.3.3` R3 进程生命周期修复

生产 `CwlDocker` 固定加入 Docker init、`SIGTERM` 停止信号和 30 秒容器停止期限。容器内监督程序使用独立进程组启动 Toil leader；第一次 `SIGTERM` 或 `SIGINT` 被转发后等待 20 秒，超时才发送 `SIGKILL`，并最多再等待 5 秒。重复信号不会延长期限。只有 Toil 子进程真正退出后才原子写入包含 schema、epoch、返回码、终止信号和强制标记的退出事实；旧格式继续兼容，错误 epoch、非法类型和不完整 JSON 均不作为可信退出。

Execution 取消先执行 `docker stop --time 30`，宿主命令最多等待 35 秒；通信失败后重新 inspect 原容器，只有确认仍运行才执行一次 `docker kill`。只有容器已停止或已确认不存在，任务才进入发布中止与取消收敛。原容器名、JobStore、epoch、节点身份、预算、授权、bridge 协议、`--disableChaining true` 和 `--maxCores 2` 均未改变。R3 没有公开接口或数据库迁移，Execution schema 仍为 `0003_workflow_trace`。

新增测试覆盖生产容器安全参数、优雅停止、强杀兜底、新旧退出事实、部分写入、`SIGTERM`、`SIGINT`、重复信号和启动竞争。真实 HTTP/Toil 回归新增两条确定性场景：排队期间取消时不创建引擎；测试代理阻塞 bridge 成果下载时取消，容器、预算和发布均正确收敛。正常成功、节点失败、运行中取消和 JobStore 恢复还会直接检查 Docker init、非 root、只读根、能力删除、PID 为 0、`docker top` 无残留进程及 Toil 回收警告为 0。
