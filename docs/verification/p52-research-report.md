# P5.2 / 0.6.1 研究协议与策略阶段报告

> HISTORICAL. P5.2 / 0.6.1 阶段记录；当前发布以机器可读 Release pointer 为准。

## 完成内容

P5.2 已在 P5.1 和 P4 执行平台上完成，未进入 P5.3。

- Platform 新增独立迁移 `0007_research_policy`，保存不可变分析修订、正式登记、观察水位、主张修订、类型化来源关系和策略决定。旧任务、Action、预算、成果与验收记录不改写。
- 新增四组公开路由，用于创建分析修订、登记分析、创建主张和读取任务的 Research 聚合视图。所有写请求保持幂等、当前角色检查和任务要求版本检查。
- AssetRef、EvidenceRef 和 ExecutionRef 均按权威服务或 Platform 账本精确核验。EvidenceRef 必须来自精确正文读取并带读取回执；SearchHit 不能成为正式来源。
- `DECLARED_PROVENANCE` 与 `OBSERVED_PROVENANCE` 分开保存。协议输入与方法属于计划来源；实际读取的证据、已观察执行和主张依据属于实际来源。
- 分析修订由不可变事实推导 `EXPLORATORY / REGISTERED / SUPERSEDED`。正式登记保存登记前已读证据与已存在执行，避免事后登记伪装成预注册。
- ClaimRevision 支持描述、关联、预测和因果命题，保存对象、范围、数量、单位、限制和精确来源。`SUPPORTED` 要求至少一个 `SUPPORTED_BY` 来源，但不冒充 P5.3 的独立科学验收。
- 实现标准库纯函数策略 `groundwater-head-comparison-v1@1.0.0`，检查监测点身份、量的类型、可换算单位、垂向基准或来源明确的转换、时间范围和聚合口径。
- 现有 Operator 和 Workflow 请求新增可选 `research_context`。不声明策略依赖的旧请求和独立统计/制图保持原行为；显式依赖地下水比较策略时，Action 准入要求冻结决定为 `APPLICABLE`。策略快照随 Action 保存，新修订不改变旧执行。
- 九个 Python 发行包及 CWL runtime 统一提升为 `0.6.1`；Data、Execution 和 Knowledge schema 保持原版本。

## 问题处理

实施中发现并关闭以下问题：

- Claim 请求校验器被继承到响应模型，导致首版主张响应误判为“后继修订缺字段”。响应模型改为独立不可变契约并增加回归。
- P5.2 Alembic 索引和约束最初未完整镜像到 SQLAlchemy metadata，迁移漂移检查失败。补齐命名索引、唯一约束和检查约束后，重复迁移与 metadata 比较通过。
- 健康阶段与 OpenAPI 精确路径回归仍停留在 P5.1。现已更新为 P5.2 并覆盖四条新增路由。
- 分析记录最初在同一事务内插入后更新恢复元数据。现改为先核验所有来源，再一次插入完整记录，仓储不再暴露修改分析载荷的方法。
- 新增可选研究上下文可能改变旧执行幂等摘要。HTTP 适配器在字段为空时移除该字段，并由旧请求回归证明兼容。

## 范围与限制

当前支持精确、可审计的研究记录和局部策略判断，不自动证明现实观测真实性。自然语言资料不会自动变为结构化事实，也不会自动裁决冲突。方法引用在 P5.2 是冻结声明；平台没有开放上传策略、用户表达式、检查器代码或 Agent 生成规则的入口。

当前算子目录没有新增“地下水头比较”计算算子。策略准入只在调用者明确声明该行动依赖该策略时阻塞；普通剖析、格式转换、单序列描述、空间处理和制图继续运行。P5.3 才会实现通用 CoveragePlan、独立检查、探索/验证交付等级、人工评审和证据失效传播。

测试使用仓库内确定性合成事实和文件，不把它们表述为真实地下水观测或现场证据。

P5.2 全部必测项通过，发布版本为 `0.6.1`。本轮结束，不自动进入 P5.3。
