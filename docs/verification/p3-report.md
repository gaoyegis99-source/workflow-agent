## 实际交付

- 独立 Data 服务及导入 Worker：明确类型的 UTF-8 CSV / 平面 Parquet、稳定字段 ID、原件和规范化表示、精确版本引用、追加语义修订、内容下载。单文件 20 MiB、10 万行、128 列。
- 两个登记算子：完整率与描述性线性趋势；显式分组、日历范围、时区、单位和缺失标记。趋势采用 NumPy；缺少样本输出无法评估，常量序列 R² 未定义；无显著性、预测和因果结论。
- 独立 Execution 服务及容器 Worker：稳定 Action/Execution/Attempt/容器关联，排队与已执行分开，启动前许可、单次启动、资源限制、取消、重启定位与输出收集。生产应用使用真实服务适配器。
- Data 发布仲裁：固定候选和摘要，文件完整后 READY，资产组和发布回执同事务可见；代次隔离、响应丢失恢复、发布与中止竞争。
- Platform 候选与验收：冻结结构化要求、三次预算闭环、不可变候选及报告、独立 Decimal 检查、当前要求/控制/活动复核后提交 COMPLETED。错误成果 FAIL 不能换键重复抽验；检查 ERROR 必须显式重试并重新计预算。
- 同源最小任务页：项目、上传、字段和语义配置、DIRECT 任务与精确授权、分别计算、下载、候选、验收、控制和清理状态；刷新后重新鉴权并从 API 重建状态。令牌只放内存。
- 八包构建安装、三个独立迁移链、隔离数据库/角色、显式配置和启动脚本、统一验证入口、合成测试数据及文档。

公开接口见 [API 与科学契约](../p3-api.md)，部署与升级见 [运行说明](../p3-operations.md)。原 P2 控制接口与 CommandReceipt 保持兼容；新增 UploadReceipt 和 AcceptanceReceipt 不混入 ExecutionRef。`activities` 查询供页面恢复执行关联。没有生产故障注入或任意写入验收结果的接口。

## 测试发现与处理

| 问题 | 修复和回归证据 |
| --- | --- |
| 接受回执已有 Execution ID，但尚未真正启动 | 观察扩展 QUEUED / executed=false；命令关联与预算消耗分开；真实容器测试验证排队时 reserved=1、used=0 |
| P3 可选默认字段改变旧 P2 幂等请求摘要 | 正式回归先复现升级后旧键 409；只规范化新增功能的空默认值，保留原字段和非默认许可。旧 Task 创建、要求修订、grant 在升级后恢复原记录；真正新增许可仍返回冲突。45 项定向回归通过，安装验证也增加旧键真实 HTTP 重放 |
| 通信未知标记残留，成果已发布仍不能收敛账目 | 最近有效事实和通信恢复分开；确定终态及同版本 RUNNING 恢复清除通信故障；检查只结算一次 |
| 接收请求之前的取消封存产生虚假执行关联 | SEALED 墓碑返回 execution_id=null；迟到同 Action 提交仍被封存，不能获得不属于项目的占位身份 |
| 启动意图持久化后进程中断 | 不重发 start；确认从未启动后先持久停止意图，再移除原容器；Data 中止失败保留预留，恢复后释放一次。真实 Docker 与 Data 断线组合验证 |
| 原容器在未知启动窗口消失，取消可能错误声称未执行 | 保持未知，不调用发布中止作为“未执行”证据；实际已执行标志不可回退 |
| 检查报告 JSON null 与 SQL NULL 条件不一致 | 按 QUEUED 状态提交报告；完成事务读取不可变报告并重新校验 Task。完整闭环和竞争测试通过 |
| Data 应用层残留 SQL、Execution 编排混入装配入口 | SQL 集中在仓储，运行编排使用注入端口；增加应用层禁止直接依赖适配器的反例检查 |
| PostgreSQL 初始化就绪与宿主机连通性 | TCP 健康检查；独立桥接网络仅发布回环端口。实际 Compose 启动、三角色迁移和重复迁移测试通过 |
| 安装验证的预算收敛等待在并行负载下偏短 | 测试等待上限由 12 秒改为 45 秒；不改变生产 HTTP 超时和租约。仓库外完整闭环已定向通过 |

一次定向运行遇到 Docker `run` 60 秒超时，未形成通过证据；已清理该次临时资源并重新验证。最终统一结果仍以最后一次完整成功运行判定。

补齐旧幂等键重放回归时主动中止了一次尚未完成的统一运行（当时 306 项通过），该次结果不计为阶段通过；修复后重新运行完整入口。
