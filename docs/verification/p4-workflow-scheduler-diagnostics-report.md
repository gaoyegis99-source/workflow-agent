## 六类根因的观测结果

1. **协调资源压低真实计算并发。** A 组实际峰值并发固定为 `2`，有效并行度中位数 `1.293`，4 个 Platform 槽位利用率只有 `32.3%`。增加到 4 Worker 后并行度仍只有 `1.389`。
2. **CWL 图包装存在可测成本。** 嵌套图生成 5 个文档，直接图 4 个；A 与 E 的总耗时中位差为 `40.303` 秒。
3. **稳定节点身份仍与 Toil 作业上下文耦合。** R1 按计划保持 `--disableChaining true`，因此没有把 chaining 变化混入本轮；该结构约束已由 trace 的调用路径、epoch 和节点 Action 关联验证，性能因果对照留给 R4/R5。
4. **bridge 把查询实现为重复 POST。** A 组每次 8 节点工作的 POST 中位数为 `277`，即每节点约 `34.6` 次。
5. **单 Worker 偶发放大领取排队。** A 组最差队列 p95 为 `2943.957 ms`；2 Worker 降至 `491.289 ms`，4 Worker 仅进一步降至 `484.347 ms`。
6. **子进程回收影响明确。** 无 init 的嵌套组每次有 `17` 条回收警告，init 三次均为 0；bridge 返回到引擎退出的中位数从 `21374.316 ms` 降至 `15824.833 ms`。

- R2 使用 **2 个 Execution Worker**：这是三次运行中最差队列 p95 不超过 500 ms 的最小值；4 Worker 的进一步改善不足 10%。
