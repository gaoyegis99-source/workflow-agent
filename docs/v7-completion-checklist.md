## 1. 如何使用本清单

### 1.1 状态规则

- `[ ]`：尚未完成。
- `[x]`：已由当前源码、结构化证据和权威报告共同证明完成。
- `BLOCKED`：存在明确外部阻塞，必须记录阻塞对象、首次出现时间和解除条件。
- `DEFERRED`：已经通过 ADR 明确排除出本次完成目标，并说明用户影响、替代路径和重新评估条件。
- 不允许仅凭代码存在、单元测试通过、历史报告或人工口头确认勾选完成。

### 1.2 每项完成必须同时满足

- [ ] 实现已进入受控源码和发行构建范围。
- [ ] 正向、反向、竞争、恢复和权限用例均有测试。
- [ ] 测试命令、输出、环境身份和摘要进入结构化证据。
- [ ] 受影响的完整兼容回归通过。
- [ ] wheel、镜像、前端资源和 Catalog 进入同一 Release Lock。
- [ ] 运维、升级、回退和已知边界文档同步更新。
- [ ] 当前发布报告和机器可读指针一致。

### 1.3 100% 完成定义

只有同时满足以下条件，才可宣布“V7 当前目标 100% 完成”：

1. G0–G9 全部门禁为 `PASS`。
2. 所有必须项已勾选；条件能力已经实现，或有批准的 ADR 明确排除。
3. 没有未关闭的 Critical/High 发现；Medium 发现必须修复或有带到期日的风险接受记录。
4. 当前 Release pointer、Release Lock、源码摘要、镜像摘要、报告和运行实例完全一致。
5. 完整业务回归、发行包安装、N-1 升级、备份恢复和安全发行验证全部通过。
6. 文档不再把已完成阶段标为“未开始”，也不使用历史测试数字描述当前发布。

### 1.4 门禁权重

权重用于展示剩余收口进度，不替代通过条件。门禁只有 `PASS` 才取得全部权重；`PARTIAL` 不取分。

## 2. 总体执行顺序

严格按以下顺序推进。每一阶段通过后再进入下一阶段，避免后续工作建立在漂移的发行身份上。

1. **阶段 0：冻结当前基线并修正文档事实。**
2. **阶段 1：关闭当前全量证据中的两个明确限制。**
3. **阶段 2：实施 P8.3 性能、资源与组合故障门禁。**
4. **阶段 3：实施 P8.4 安全扫描、签名和离线发行。**
5. **阶段 4：确定并验证灾备、高可用、RPO/RTO 边界。**
6. **阶段 5：补齐科学验收、重验和知识可信状态。**
7. **阶段 6：补齐知识文档解析与生产检索链路。**
8. **阶段 7：按真实业务需求完成或正式排除 Join 等扩展能力。**
9. **阶段 8：补齐访问、可观测性、告警和运行体验。**
10. **阶段 9：构建最终统一 Release，执行全门禁并移交。**

### 5.4 资源上限破坏性测试

- [ ] 过大输入、压缩炸弹、异常 Parquet、GeoPackage、GeoTIFF 和文档均被有界拒绝。

### 5.5 组合故障矩阵

- [ ] Platform API/Worker 在准入、发送、观察和结算各阶段终止。

- [ ] PostgreSQL 短时断连、重启、连接耗尽和事务中断得到保守恢复。
- [ ] HTTPS 远端 peer 断线、404、重启、输出断流和证书错误保持正确未知状态。
- [ ] 多个故障按固定顺序组合后，Action、Execution、预算和 Publication 仍唯一。

### 5.6 P8.3 交付物

- [ ] 增加独立的 P8.3 检查入口，不改变 P8.2 历史证据。
- [ ] 生成性能原始数据、统计摘要、结构化证据和阶段报告。

## 7. 阶段 4：灾备、高可用与恢复目标（G4）

## 9. 阶段 6：Knowledge、文档解析与生产检索（G6）

目标：扩展知识来源，同时保持精确引用、不可变身份和失败关闭。

- [ ] 查询无结果、服务不可用、超时和模型错配具有不同公开状态。

### 9.5 G6 通过标准

- [ ] Embedding 只有通过完整生产门禁才启用。

## 10. 阶段 7：多输入计算、Join 与能力边界（G7）

目标：对当前明确延期的能力作出可执行决定，避免无限期保持模糊状态。

### 10.1 真实 Join 用例决策

- [ ] 收集至少一个真实的一对一或一对多地下水数据 Join 用例。
- [ ] 明确左右数据角色、键、null 语义、基数、输出字段和最大放大倍数。
- [x] 如果没有真实用例，建立 ADR 将 Join 排除出当前完成目标，并记录重新评估条件。 现有 Join 范围 ADR 已正式排除当前目标并记录重评条件。见[决定记录](decisions/v7-conditional-capabilities-scope.md)。
- [ ] 如果有真实用例，进入 P7.3b；不得直接在算子容器中私自读取第二个文件。

### 10.2 P7.3b 多输入基础

- [ ] 新增判别明确的双输入公开契约，保留旧单输入兼容。
- [ ] Platform 分别解析、授权并冻结左右 TableSelection 和摘要。
- [ ] Execution 按受信端口分别暂存只读文件并检查 schema/摘要。
- [ ] Publication manifest 保存左右 AssetRef、角色、来源路径和工作流身份。
- [ ] 工作流允许两个输入分别来自根资产或不同上游节点。
- [ ] Agent TaskSpec 冻结左右角色，模型不能交换输入、键或基数。
- [ ] 建立测试专用双输入算子证明授权、恢复和 provenance，不提前实现 Join。
- [ ] 独立 checker 同时取得两张精确源表。

### 10.3 P7.3c 受限 Join

- [ ] v1 只支持 INNER/LEFT 等值 Join。
- [ ] 键只接受完全相同的 string/int64/bool，不隐式 Cast。
- [ ] 固定 `nulls_equal=false`。
- [ ] 只允许 ONE_TO_ONE、ONE_TO_MANY、MANY_TO_ONE；拒绝 MANY_TO_MANY。
- [ ] `max_output_rows` 必填，并同时受成果字节上限约束。
- [ ] 物化前计算输出规模，超限失败且不截断。
- [ ] 输出顺序、字段投影和名称冲突规则完全冻结。
- [ ] `tabular-join-reproduction-v1` 独立复算左右输入、匹配关系和输出。
- [ ] 覆盖直接执行、Agent、工作流、响应丢失、取消、恢复和失败不发布。

### 10.4 其他条件能力的范围决定

以下每项必须实现或用 ADR 排除：

- [ ] 高级表格：median、标准差、分位数、时间分桶、窗口和 HAVING。
- [ ] 远程执行：多 peer 选址、负载均衡、远程 QGIS、远程 Toil leader。
- [ ] 制图：PDF、GeoPDF、栅格、在线底图、QPT/QML 和交互编辑器。
- [ ] CWL：JavaScript、ExpressionTool、Shell、外部 import/include、用户镜像。
- [ ] Studio：Marketplace、跨项目共享、实时协作、跨平台导出。
- [ ] Agent：多 Agent、Agent authoring、动态工具或用户代码。

涉及任意代码、用户镜像和动态插件的能力默认保持关闭；若实现，必须先增加单独的隔离、权限和检查器架构，不得删除现有安全边界。

## 14. 发布前最终核对表

- [ ] 输入、语义、方法、执行、输出和证据身份均不可变且可追踪。

- [ ] 外部流量使用 TLS。
- [ ] 用户、服务、数据库、远端和模型凭据均可轮换和撤销。

### 可靠性

- [ ] Action、Execution、预算、Publication 和 Agent 调用具有唯一身份和保守恢复。

### 性能与运维

- [ ] 保留和清理策略不破坏审计证据。
