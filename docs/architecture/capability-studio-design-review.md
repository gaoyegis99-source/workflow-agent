# 算子与工作流工作台：评估反馈与修订记录

日期：2026-10-16。评估对象：前序对话建议与实施计划草案。当前文档：[分轮实施计划 v1.3](capability-studio-implementation-plan.md)。本文保留首次 19 项反馈，并记录二次评估 7 项反馈及完成审计结果。

性质：基于本地源码、已查阅的开源项目官方资料和故障场景进行的设计复评。**这是同一执行者完成的设计检查，不是独立第三方审计，不是软件验收。** 本次只修改文档；没有运行新的业务测试，没有确认任何拟新增功能已可用。

## 1. 结论

保留“独立前端 + Platform Authoring 模块 + 原执行链路”的方向。将原建议细化为 A1–A5；第一轮仅实现目录描述、草稿和发行基础，A3 才交付完整工作流编辑运行闭环。

评估认为原方向可行，但直接按概念方案开发会遗漏候选可见性、事务关联、目录快照、前端精度和发行材料约束。下表中的修改已合入计划，**状态均为设计已修订，实现与测试待对应轮次完成**。

## 3. 复杂度评估与取舍

| 选项 | 结论 | 理由 |
| --- | --- | --- |
| 新建独立 Registry 微服务及数据库 | 当前不采用 | 会新增跨服务发布、身份和事务问题；当前规模用 Platform 子模块足够 |
| 独立前端工程 | 采用 | 画布和表单复杂度已超出当前静态任务页；仍同源交付 |
| 全量迁入 Galaxy/QGIS Modeler | 不采用 | 会引入不同执行和节点语义，难以保持 V7 现有预算与恢复证据 |
| React Flow 画布 | 采用 | 复用交互组件，后端仍掌握定义与契约 |
| 任意算子插件动态安装 | 不采用 | 当前系统没有对应安全、契约和独立 Checker 接入机制 |
| 在线目录热更新与撤销仲裁 | 不采用 | 与已确认的停机更新边界不符；本轮不增加发布竞争协议 |
| 参数 Schema 全部手写到前端 | 不采用 | 漂移风险高，既有 DTO 和服务端规则应继续权威 |
| 前端完全不支持高级工作流时简化保存 | 不采用 | 会丢失条件、scatter 和身份；只读比破坏性保存更可靠 |
| 试运行自动建立任务、授权和预算 | 不采用 | 跨多个用例的自动化会掩盖权限和账目，先要求显式已有任务 |
| 实时多人协同 | 延期 | 乐观锁和显式修订即可满足首期，避免冲突合并复杂度 |
| 受限源码导入 | A5 才实施 | 先验证图形生成与后台语义，再处理解析与往返编辑 |
| 算子参数预设库 | 延期独立评估 | 当前可用工作流默认参数满足基础复用；本计划不额外创建预设版本系统 |

本次评估主动压缩了自动化范围。模块必须可用，但不承诺在第一版实现“任意包安装、任意工作流编辑、自动授权和一键部署”。

## 4. 场景推演与设计结果

### 4.1 校验后修改草稿

原 revision 3 校验通过，用户保存 revision 4。新 head 不改变旧 validation；revision 4 不能借用 revision 3 的校验。用户仍可明确选择 revision 3 的候选发布，前提是环境和试运行证据有效。

结果：支持真实历史版本，不用“必须最新”掩盖身份问题。

### 4.2 试运行已接受但浏览器断线

Action、Trial、预算和 outbox 同事务提交。浏览器使用原幂等键重放，得到原 trial/Action；Worker 不依赖浏览器继续执行。查询 UNKNOWN 时不会换候选或重新计算。

结果：复用原恢复协议，新增模块没有第二套调度。

### 4.3 目录在排队期间升级

旧校验保存目录 A，Worker 当前只有目录 B。不得用 B 完成 A 的校验。旧记录保留，显示环境已变化；用户发起新校验和候选。

结果：历史证据不改写，当前能力不伪装成旧环境。

### 4.4 算子申请审核后修改材料

审核决定引用申请 revision 2；申请 revision 3 修改输出 Schema。revision 2 的审核不能覆盖 revision 3；当前部署能力由实际 catalog 与 release lock 匹配决定。

结果：审核不是可移动的勾选状态，编辑内容不能直接改变执行权限。

### 4.5 测试执行成功但无领域检查器

workflow release 可以保存明确的运行样例证据，但不能把 Task 标记为 VERIFIED。具体任务仍由 CoveragePlan 和 Checker 判断，未知能力保持未覆盖。

结果：模块增加操作便利，不削弱 P5 科学验收边界。

### 4.6 数据校验失败且兄弟节点成功

沿用现有父工作流原子发布。Studio 查询真实父/节点事实并显示失败；成功兄弟的私有输出不能被 UI 当作已发布成果下载或登记交付。

结果：编辑链路不创造绕过 Data 发布仲裁的文件接口。

以上为设计推演；必须由实施计划对应真实测试确认，不能作为已经通过的故障注入证据。

## 5. 仍需在实施中验证的事项

1. 三个只读探针已证明 DTO 导出 Schema 不包含全部规则；A2 仍须验证特殊控件、后端错误定位和无损往返。
2. 从已有 PackageProcessor 提取共享编译上下文时，旧包的 manifest 摘要是否逐例保持不变。
3. Trial 原子关联如何最小化修改共享准入用例；先加事务失败测试，再抽取接口。
4. v1.2 保持原 release lock 格式；验证完整 wheel 安装核验、包内资源和确定性派生链，不能以版本字符串相同代替文件摘要。
5. 前端序列化、数值类型、Unicode 和字段顺序是否与服务端规范 JSON 一致。
6. A5 高级图能否完整投影现有受限 CWL；不支持部分必须保持只读，不降低既有服务端能力。

这些是实施门槛，不是需要用户再次决定的常规实现选项。实现不满足时留在当前轮修复，不静默降低验收要求。
