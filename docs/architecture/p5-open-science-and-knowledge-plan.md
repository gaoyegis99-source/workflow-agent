# P5 开放式科学策略与知识方案

状态：P5.1 / `0.6.0`、P5.2 / `0.6.1` 和 P5.3 / `0.6.2` 均已有实现；审计修复已作为 P5-R0 / `0.6.3` 发行并通过完整门禁。修复覆盖生命周期事件兼容、跨任务执行来源、检查计划新鲜度、通用检查器过度判定和检查报告绑定；尚缺的领域检查器与重验能力见 [P5 逻辑审计](../verification/p5-logic-audit-report.md)，发行证据见 [P5-R0 报告](../verification/p5-r0-release-report.md)。P3 的 `p3-timeseries-v1`、既有 API 和历史验收保持原状。

## 1. 设计决定

科学内核不预设“所有研究都是地下水时间序列”，也不要求每个任务绑定一个预制 `ScienceProfile`。平台统一管理身份、版本、来源、授权、预算、行动和验收事实；具体数据含义、方法前提和判断标准由与任务及所用能力相称的版本化契约描述。

自由度体现在：允许新数据类型、新领域、用户指定的方法和探索性问题；知识库可以提供资料，但不是每项任务的必经步骤。底线是：执行前能说明用了什么输入和方法，交付时能说明哪些要求已检查、哪些结论有证据、哪些仍无法判断。没有受信判据时，不把“运行成功”或 Agent 的自评写成科学 PASS。

| 层次 | 稳定内容 | 可扩展内容 |
| --- | --- | --- |
| 平台事实 | AssetRef、表示摘要、语义修订、来源关系、Action/Execution/CheckResult 身份 | 不定义统一的水文或统计字段清单 |
| 数据能力 | 媒体类型、结构描述、可用查询、可核实的元数据 | 表格、空间、栅格、文档、模型文件分别提供类型适配 |
| 领域规范 | 规范 ID、版本、适用条件、所需事实及判定器身份 | 地下水观测只是可选规范之一；其他领域可独立登记 |
| 研究协议 | 任务目标、输入范围、选定方法、输出角色和实际结论范围 | 可从轻量描述逐步扩展；不是固定六步状态机 |
| 验收 | 用户要求的覆盖映射、已运行检查、未覆盖项及限制 | 参考计算、性质检查、数据对照或有范围的人工评审 |

P3 的 `f0/f1/...` 是平面表格表示中的稳定列身份，不是全平台资产的物理结构。`p3-timeseries-v1` 是一个已实现的固定验收模板，不能提升为所有 P5 任务的默认科学规范。旧任务和报告继续按冻结版本解释。

## 2. 事实、声明与适用性

Data 保管原始字节、表示、技术元数据、语义修订和发布事实。Knowledge 保管资料正文、定位、索引和生命周期。Research 在 Platform 记录某任务如何使用这些内容；它不复制 Data/Knowledge 的权威事实，也不把检索摘要当成正文。

每条影响方法或结论的语义声明记录：所指对象与属性、值及单位或规范引用、适用范围、声明者或机器来源、原文位置、绑定的资产/正文版本、登记时间和核验状态。核验状态区分“仅声明”“经格式或一致性检查”“经独立外部依据核实”“相互冲突或已撤回”；它不声称平台能仅凭文件内容证明现场观测真实。可保存候选解释，但候选不能自动升级为已确认事实。

算子按实际输入声明所需能力，例如“有时间轴和有限数值”“水平 CRS 已知”“高程基准可比”；不要求所有资产预先填满井号、垂向基准或仪器字段。只有某项分析依赖这些字段时才检查它们。跨井水位比较可以要求共同基准；单文件行数剖析不需要该条件。格式、语义和科学适用性分别报告，不用一个 `valid=true` 掩盖差别。

允许领域规范在版本化注册表中扩充条件和解释，但注册表只保存声明式元数据与已审查的判定器引用。上传的文档、模型生成的规则或工作流参数不能自动成为受信判定器，也不能扩展权限。规范冲突保留原始声明和冲突范围，由有来源的修订解决，不使用“最后写入者覆盖”。

## 3. 灵活的研究过程

任务按实际工作选择协议深度，而非按固定任务类别强制走完整流程：

1. **发现与探索：** 可以剖析未知数据、检索资料、比较候选方法。记录输入、运行和观察身份；不把探索结果伪称预先确认的结论。
2. **正式计算：** 冻结本次行动必需的输入、语义依赖、方法实现和参数；只阻塞依赖仍未知事实的行动。新发现导致新修订，旧执行仍指向旧版本。
3. **形成结论：** 以 `ClaimRevision` 明确命题类型、对象与时空范围、所依赖的结果或资料、限制，以及“描述/关联/预测/因果”等解释层级。无需正式科学主张的转换任务不强制创建 ClaimRevision。
4. **交付验收：** 从用户冻结要求、所选方法和拟交付主张生成要求—检查覆盖表。能够自动核验的运行检查；需要领域判断的按事先约定的范围评审；无法核验的保持 `UNVERIFIED` 或 `INDETERMINATE`，不能自动完成要求它必须通过的任务。

`AnalysisRevision` 可为空、简短或完整。正式比较、预测或假设检验才要求与其声称的证据强度相称的比较规则、数据划分和停止规则。探索之后改变方法必须留下已观察结果和修订原因；用户可以修改交付要求，但 Agent 不能自行降低必要条件。

检查计划采用**按要求和主张的局部组合**：平台底线检查始终存在；领域规范和方法只增加实际适用的检查。领域规范不适用时记录理由，而不是硬塞给所有任务。系统给出每一项必要要求的 `CHECKED`、`REVIEW_REQUIRED`、`UNVERIFIED` 或 `NOT_APPLICABLE_WITH_REASON` 覆盖状态；只有已证明适用且通过的检查，或事先允许的替代交付，才能满足该要求。用户没有提出正式科学验证要求时，可交付明确标注为探索性或未验证的成果，但不能把它标成科学上已证实。

## 4. Knowledge 的角色和接口边界

Knowledge 是**可选的、带来源的资料服务**：搜索用于发现，精确正文读取才可生成正式引用。文件自描述元数据、用户说明、数据字典、外部标准、受信执行回执同样可以为任务提供事实。资料内容不能直接修改任务、授权、算子目录或检查器代码。

正式引用包含正文版本、片段定位、内容摘要、读取回执、生命周期版本及所支持主张的范围。对可变网页或外部 API，先按授权保存可复核快照；仅有 URL、检索命中或对话摘要不能成为长期可核查的正式依据。过期、撤回、权限变化和互相冲突分别表达；历史引用保留当时内容，新交付重新核对当前适用性。

检索可按任务使用关键词、结构过滤、语义召回或直接提供资料；第一版不强制向量检索，也不要求“引用不能为空”。质量评测同时比较直接提供、基础检索和新检索策略，避免因为召回得更多就误判结论更好。检索无结果与服务不可用必须区分。

## 5. 内部契约与对外接口

P5 延续现有 `GET P/tasks/{task_id}/research`、知识导入/搜索/精确读取、缺项回答和候选验收路由；新增公开写入接口仅在有真实用例时定义，不开放任意 `set_fact`、任意验收结果或用户上传检查器代码。`P` 仍为 `/api/v1/projects/{project_id}`。

内部端口的方向如下；类型名是设计语义，不要求一开始建立同名表或新服务：

```text
DataPort.describe(asset_ref) -> RepresentationFacts + SemanticAssertions
KnowledgePort.read(evidence_ref) -> ExactContent + Lifecycle
Research.record_observation(source_ref, scope, receipt) -> ObservationRef
Policy.evaluate(action, required_capabilities, facts) -> Applicable | Missing | Conflict
Acceptance.plan(requirements, claims, method_contracts, facts) -> CoveragePlan
Acceptance.evaluate(candidate, coverage_plan) -> CheckResults + UnverifiedItems
```

`Policy` 和 `Acceptance` 只通过端口读取别的服务，不直接查其表。输入绑定继续固定资产字节、表示、语义修订和所用规则版本；领域扩展通过版本化能力契约表达，不在通用 `AssetRef` 中不断增加必填字段。API 回执应区分“资料已找到”“正文已读取”“语义已声明”“声明已核实”“结论已检查”，不能全部压成 `verified`。

## 6. P5 分段实施与验收

P5 开始后仍按“一轮只实施一个阶段”的规则执行；本节是 P5 内部开发次序，每项通过定向测试才继续下一项，不提前做 P6 Agent。

| 顺序 | 开发 | 必测结果 |
| --- | --- | --- |
| S1 | 通用来源/声明/覆盖契约及 P3 兼容迁移 | 旧任务、旧报告和 P3 验收不变；表格以外类型不被强制填时间序列字段；跨项目拒绝 |
| S2 | Knowledge 导入、精确读取、生命周期和检索对照 | 搜索命中不能冒充已读正文；撤回、冲突、无结果和不可用可区分；引用能定位原文版本 |
| S3 | 按能力检查的可选领域规范、非表格元数据适配、缺项及研究修订 | 缺垂向基准只阻塞依赖它的比较；独立剖析仍可运行；非表格资产不伪装成 f0/f1 表；新修订不改写旧结果 |
| S4 | 按要求/主张组合的检查计划、报告及失效传播 | 自定义要求未覆盖时不能伪 PASS；错误数值、伪造引用和错误结论范围被拒绝；允许的探索交付标明未验证 |
| S5 | 真实案例对照与完整回归 | 至少覆盖地下水时间序列、非地下水表格及一种非表格资产；P0–P4 必要回归通过，并记录检查成本和人工评审范围 |

验收重点不是“所有任务自动通过”，而是允许不同任务选择不同方法，同时任何完成记录都准确陈述检查过什么。P5 不实现自主 Agent；P6 再评估模型在这些接口上的选择、澄清和修复质量。
